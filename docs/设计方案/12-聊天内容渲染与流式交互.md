# 聊天内容渲染与流式交互

> 版本：0.1  
> 日期：2026-08-02  
> 状态：待用户审核  
> 范围：聊天消息内容渲染、状态事件、流式更新与消息滚动；不包含真实模型、工具、文件或后端业务实现

本方案是 [04-代理与聊天](./04-代理与聊天.md) 中消息内容和流式章节的细化规范。聊天模式与代理模式继续共享同一消息 UI，但聊天模式仍禁止工具、网络检索、文件写入和其他副作用能力。

## 1. 目标与边界

### 1.1 目标

- 支持 GFM Markdown、KaTeX 数学公式、代码语法高亮和 Mermaid 图表。
- 用 `Message`、`MessageScroller`、`Marker` 表达消息布局、唯一滚动区和运行状态。
- 流式输出稳定追加，避免整条消息替换、内容闪烁和滚动位置抢夺。
- 保留正文、代码、表格和 Mermaid 源码的选择与复制能力。
- 让等待、思考、审批、工具执行、完成、失败和取消状态可观察、可恢复。

### 1.2 不在本方案内

- 真实模型连接、Wails 事件协议、工具执行、网络检索和文件写入。
- 真实 SVG/PNG 文件保存路径。当前只设计并展示前端 Mock 导出流程。
- 将消息渲染结果持久化为 HTML、AST、SVG 或截图。

## 2. 组件基线

### 2.1 消息与滚动

聊天区域只保留一个主要滚动容器，采用 shadcn/ui 官方聊天组件：

- `MessageScrollerProvider`：保存滚动状态、自动跟随和阅读位置。
- `MessageScroller`：消息滚动框架。
- `MessageScrollerViewport`：唯一可滚动视口。
- `MessageScrollerContent`：消息日志/实时内容区域。
- `MessageScrollerItem`：每条消息或系统事件的稳定锚点，必须提供稳定 `messageId`。
- `MessageScrollerButton`：回到最新消息、显示未读新增数量。
- `Message`：提供用户、助手、系统和工具消息的统一排列。
- `Bubble`：只用于用户消息和短系统回执；助手长回复使用平面正文布局。

官方组件文档：

- [Message](https://ui.shadcn.com/docs/components/aria/message)
- [Message Scroller](https://ui.shadcn.com/docs/components/aria/message-scroller)

不再为聊天消息区自行维护另一套 `ScrollArea` 滚动监听、底部判断和自动滚动逻辑。侧栏、文件树、工具面板仍可使用普通 `ScrollArea`。

### 2.2 状态标记

`Marker` 用于活动状态、系统事件、引用和流式光标；正在变化的状态使用 `role="status"` 和克制的 `aria-live="polite"`，稳定历史事件不持续播报。

官方组件文档：[Marker](https://ui.shadcn.com/docs/components/aria/marker)

## 3. Markdown 内容管线

### 3.1 处理顺序

消息只保存 Markdown 源文本，渲染时按以下顺序处理：

1. `react-markdown` 解析 Markdown。
2. `remark-gfm` 增加表格、任务列表、删除线和自动链接。
3. `remark-math` 识别 `$...$` 和 `$$...$$`。
4. `rehype-raw` 仅在受控白名单管线中解析 HTML。
5. `rehype-sanitize` 应用 Aestival 自定义安全 schema。
6. `rehype-katex` 将公式渲染为 KaTeX，并加载对应 CSS。
7. 自定义 `code` 组件处理代码块；`mermaid` fenced block 转交 `MermaidBlock`。

`react-markdown` 默认以 React 节点安全渲染，并通过 remark/rehype 插件扩展 Markdown 能力：[react-markdown](https://github.com/remarkjs/react-markdown)。

### 3.2 支持的 Markdown

- 标题、段落、分隔线、强调、删除线、引用和嵌套列表。
- 有序/无序列表、任务列表；任务复选框只读且不可改变消息内容。
- GFM 表格；列数较多时使用消息内部的横向滚动区。
- 链接、自动链接和脚注；外部链接强制使用安全协议和 `rel="noreferrer noopener"`。
- 行内代码和 fenced code block。
- `$...$` 行内公式、`$$...$$` 块级公式。
- `mermaid` fenced code block。

### 3.3 安全 HTML 子集

允许的 HTML 仅用于文本语义和结构补充，包括：

- `strong`、`em`、`del`、`s`、`mark`、`kbd`、`sub`、`sup`、`br`。
- `details`、`summary`。
- 标题、段落、列表、引用和表格结构标签。
- `a` 的 `http`、`https`、`mailto` 链接。

禁止：

- `script`、`style`、`iframe`、`object`、`embed`、`foreignObject`。
- `on*` 事件属性、任意 `style`、任意资源加载属性。
- 原始 HTML 图片；图片必须通过结构化附件或本地资源解析器展示。
- `javascript:`、`data:`、`vbscript:` 和协议相对链接。

清洗 schema 必须显式列出标签、属性和协议，不能使用“允许所有 HTML”的配置。渲染器生成的 KaTeX class、MathML 和高亮 token class 单独加入白名单。安全清洗参考：[rehype-sanitize](https://github.com/rehypejs/rehype-sanitize)。

### 3.4 渲染错误

任何单个块解析失败都不能导致整条消息消失：

- Markdown 失败：退回纯文本源内容。
- KaTeX 失败：保留公式源码并显示“公式渲染失败”。
- 代码高亮失败：使用纯文本等宽代码块。
- Mermaid 失败：保留源码，显示错误说明和复制入口。

## 4. 公式、代码与 Mermaid

### 4.1 KaTeX

采用 `remark-math + rehype-katex`。公式闭合前保持源码，不在流式过程中反复拆分或重排公式。公式渲染不执行脚本，不读取外部资源。

### 4.2 代码块

代码块使用独立 `CodeBlock` 业务组件，内部组合 `Tabs`（需要文件语言/视图时）、`Button`、`Tooltip`、`ScrollArea` 和普通内容分区。

统一能力：

- 显示语言标签和行数。
- 复制代码，复制成功使用 `Sonner`。
- 保存为文件入口；当前只显示 Mock 保存结果。
- HTML/CSS/JavaScript 增加“添加到应用”入口。
- 横向滚动，不强制换行破坏代码格式。
- 默认使用 Shiki token 渲染 React 节点，不把用户代码当 HTML 注入。

Shiki 按语言动态加载，首批语言为：`javascript`、`typescript`、`jsx`、`tsx`、`json`、`html`、`css`、`bash`、`python`、`go`、`rust`、`sql`、`yaml`、`markdown`。未知语言和高亮异常统一降级为纯文本。

代码块尚未闭合时使用纯文本；闭合后再进行高亮，避免流式更新期间高亮结果反复跳动。

### 4.3 Mermaid

` ```mermaid ` fenced block 进入独立 `MermaidBlock`，不作为普通代码块处理。

预览区提供：

- 源码 / 预览 Tabs。
- 放大、缩小、适应窗口和恢复默认视图。
- 复制 Mermaid 源码。
- SVG / PNG 导出入口。

流式规则：

- 未闭合代码块：显示源码和“生成中”。
- 已出现可解析内容：最多每 200ms 重绘一次。
- 解析失败：保留最近一次成功预览，不闪烁成空白或错误图。
- 流结束后立即执行一次最终渲染。

安全规则：

- 固定 Mermaid `securityLevel: "strict"`。
- 禁止 click 行为、HTML 标签、外部图片和外部链接。
- 忽略或清除会覆盖安全配置的 Mermaid 初始化指令。
- 生成的 SVG 经过 SVG 白名单清洗后再进入 DOM，禁止事件属性、`foreignObject` 和外部引用。

Mermaid 官方配置和渲染 API：[Mermaid Usage](https://mermaid.js.org/config/usage.html)。

当前导出为前端 Mock：展示格式选择、生成进度和完成反馈，不向磁盘写入文件；真实保存由后续 Wails 文件服务设计决定。

## 5. 消息结构与 UI 适配事件

以下类型是前端 UI 适配层，不是 Wails 后端协议：

```ts
type ConversationMessage = {
  id: string
  role: "user" | "assistant" | "system"
  createdAt: string
  parts: ConversationPart[]
  status?: ConversationMessageStatus
}

type ConversationPart =
  | { type: "markdown"; id: string; source: string; streaming?: boolean }
  | { type: "thinking"; id: string; summary?: string; state: "running" | "completed" }
  | { type: "status"; id: string; state: ConversationRunState; text: string }
  | { type: "tool"; id: string; toolCallId: string }
  | { type: "attachment"; id: string; attachmentId: string }

type ConversationUiEvent =
  | { type: "message-start"; messageId: string; role: ConversationMessage["role"] }
  | { type: "message-delta"; messageId: string; partId: string; sequence: number; text: string }
  | { type: "status"; messageId: string; state: ConversationRunState; sequence: number }
  | { type: "thinking"; messageId: string; partId: string; summary: string }
  | { type: "tool"; messageId: string; toolCallId: string }
  | { type: "error"; messageId: string; message: string }
  | { type: "message-end"; messageId: string; sequence: number }
```

约束：

- `sequence` 单调递增；重复事件不会重复追加。
- 流式只追加 delta，不整体替换助手消息。
- Zustand 只保存源文本、结构化附件引用和状态，不保存 AST、HTML 或 SVG。
- 当前 Mock 用同一套事件适配器模拟输出；不新增真实模型、工具或文件业务逻辑。

## 6. 消息布局与状态

### 6.1 消息布局

- 用户消息：右侧 `Message + Bubble`，正文和附件保持可选择。
- 助手消息：左侧平面 `Message`，正文不套 Card。
- 工具调用：继续使用一张独立 Card，插入消息内容流，内部不嵌套 Card。
- 思考大纲：放入对应助手消息内部的 `Collapsible`，只展示模型返回的摘要，不展示隐藏推理。
- 上下文压缩：作为 `MessageScrollerItem` 中的系统事件。
- 消息操作：复制、重新生成、朗读、分叉、导出和更多位于正文边界外，不改变正文高度。
- 当前运行状态不再单独悬浮在输入框上方；标题栏和侧栏只保留简短同步状态。

### 6.2 Marker 状态

| 状态 | Marker 文案 | 语义 |
| --- | --- | --- |
| `preparing` | 准备中 | 发送后建立运行上下文 |
| `waiting` | 等待模型 | 尚未收到模型输出 |
| `thinking` | 思考中 | 模型提供的思考摘要正在生成 |
| `streaming` | 生成中 | Markdown/代码/公式持续追加 |
| `awaiting-approval` | 等待审批 | 工具动作等待用户决定 |
| `tool-running` | 执行中 | 已批准的工具正在运行 |
| `compacting` | 压缩上下文 | 正在生成压缩事件 |
| `completed` | 已完成 | 稳定历史状态，不持续播报 |
| `failed` | 失败 | 保留已生成内容并提供重试 |
| `cancelled` | 已停止 | 保留已生成内容并提供继续/重试 |

活动状态使用 `role="status"`；完成、失败和取消使用稳定历史标记。停止、失败和网络中断不得清空已经生成的内容。

## 7. 流式与滚动体验

### 7.1 更新节奏

- 真实流式不增加人为逐字动画，以模型 delta 到达节奏为准。
- Mock 每约 30–60ms 生成一段文本，前端按约 16–33ms 批量提交更新。
- 只重新渲染当前消息尾部；已闭合的段落、代码块、公式和 Mermaid 块保持稳定。
- 代码块、公式和 Mermaid 定界符未闭合时使用源码降级，闭合后再切换渲染。
- 高亮和 Mermaid 都采用可取消的异步任务，旧结果不能覆盖新结果。

### 7.2 自动滚动

- 用户在底部时自动跟随新内容。
- 用户上滑后立即停止自动滚动，不因状态 Marker 或 Mermaid 重绘抢回位置。
- 有新消息时显示“回到最新消息”和未读数量。
- 点击“回到最新消息”后恢复跟随；键盘也可触发。
- `MessageScrollerItem` 使用稳定 `messageId`，支持后续历史加载、跳转消息和恢复上次阅读位置。

## 8. 可访问性与交互

- 消息日志提供可读的区域标签；活动 Marker 使用 `role="status"`，不逐 token 播报。
- 消息正文、代码、表格和 Mermaid 源码保持文本选择；按钮、Tabs、菜单和状态栏禁止误触选择。
- Mermaid 源码/预览 Tabs、缩放、复制和导出按钮均支持键盘和 `aria-label`。
- 公式失败、Mermaid 失败、代码降级和导出 Mock 结果提供可读文字，不只依赖颜色或图标。
- 消息、工具、附件和 Mermaid 继续使用区域化 `ContextMenu`，不恢复浏览器原生右键。
- `reduced-motion` 下关闭 Shimmer、轮播和非必要过渡；不影响内容更新。

## 9. 实现门槛与依赖

本设计审核通过前：

- 不修改 `frontend/src`。
- 不安装 Markdown、KaTeX、Mermaid、Shiki、sanitize 或 shadcn 新组件依赖。
- 不改 Wails、模型、工具、文件和后端业务逻辑。

审核通过后，按以下顺序实现：

1. 确认 Node.js 满足当前 shadcn CLI 要求，安装官方 `Message`、`MessageScroller`、`Marker` 等组件。
2. 添加 Markdown、KaTeX、Mermaid、Shiki、`rehype-raw`、`rehype-sanitize` 和 SVG 清洗依赖，并将 Mermaid/Shiki 动态分包。
3. 新增 `MarkdownRenderer`、`CodeBlock`、`MermaidBlock` 和 UI 事件适配器。
4. 迁移 `conversation-message`、`conversation-view` 与现有 Zustand Mock 状态机。
5. 执行视觉、交互、无障碍、渲染安全和生产构建回归。

## 10. 验收矩阵

### 10.1 内容渲染

- GFM 标题、列表、任务列表、表格、引用、删除线和链接正确显示。
- 安全 HTML 子集可以显示；脚本、事件属性、危险协议和外部资源不会执行。
- 正确公式使用 KaTeX 显示；错误公式保留源码且不影响整条消息。
- 支持首批代码语言高亮；未知语言显示纯文本。
- Mermaid 支持源码/预览、缩放、复制、SVG/PNG Mock 导出；错误和未闭合状态可恢复。

### 10.2 流式与状态

- 等待、思考、生成、审批、工具执行、压缩、完成、失败和停止均能通过 Marker 区分。
- 流式文本只追加、不重复、不整段闪烁。
- 停止、失败、网络中断和重试保留已生成内容。
- Mermaid 在流式中保留最近成功预览，不因临时语法错误闪烁为空。

### 10.3 滚动与交互

- 聊天只有一个主要消息滚动容器。
- 底部跟随、上滑暂停、未读数量和回到最新均可操作。
- 键盘可操作消息操作、Tabs、折叠、复制、导出和回到底部。
- 960×640、1280×800、1440×900、1920×1080 及窄窗口无横向溢出。

### 10.4 工程验证

- Markdown 标题和代码围栏完整，相关文档相对链接有效。
- TypeScript 检查和 Vite production build 通过。
- 渲染安全测试覆盖危险 HTML、链接协议、Mermaid SVG 和高亮降级。
- 检查无 Card 套 Card、无重复滚动容器、无浏览器原生右键。
- 不新增真实模型调用、网络检索、工具执行、文件写入或后端业务逻辑。
