# Aestival UI 设计方案

> 版本：0.2  
> 日期：2026-07-25  
> 状态：实现前设计基线  
> 范围：仅定义 UI、交互、状态和组件使用，不包含前端代码与后端实现

## 1. 产品定义

Aestival 是一个本地优先、无登录流程的跨平台 AI Agent 桌面工作区。核心体验是：在项目上下文中发起代理任务或纯聊天，同时在同一窗口中查看文件、终端、搜索、日志与会话调试信息。

设计目标：

1. 让“开始一个任务”成为启动后最短的路径。
2. 让代理执行过程可观察、可授权、可恢复，而不是只展示最终回答。
3. 让会话、项目、文件和工具状态始终有清晰归属。
4. 用一致的桌面交互覆盖管理页面、编辑器和多面板工作区。
5. 保持本地应用的紧凑度，不引入登录、云账户或营销页面。

## 2. 设计基线

- 技术方向：Wails 3 + React + TypeScript。
- UI 组件：Tailwind CSS + shadcn/ui，禁止用手写基础控件替代 shadcn/ui 已有组件。
- 状态管理：Zustand；本方案只描述状态域，不提供代码。
- 通用图标：`lucide-react`。
- 文件与文件夹图标：Material Icon Theme 资源。
- 代码编辑器：Monaco Editor。
- 视觉方向：参考 Codex 的克制、紧凑、低装饰、高信息密度桌面体验。
- 卡片策略：允许使用 `Card`，但卡片不是默认布局；禁止任何形式的卡片嵌套。
- 默认布局：左侧栏 + 主内容两栏；按需展开右侧检查器形成三栏；底部面板属于垂直分割，不增加列数。
- 默认状态：左侧栏展开，当前项目为系统固定项目“任务”，主区展示“新建任务”。

## 3. 核心设计决策

| 编号 | 决策 |
| --- | --- |
| D-01 | 全局标题栏始终独占第一行，不因左右侧栏的收起或展开而移动。 |
| D-02 | 全局右键禁用浏览器原生菜单，统一使用 shadcn/ui `ContextMenu`；工具栏上的点击菜单使用 `DropdownMenu`。 |
| D-03 | 全局搜索是 `Command + Dialog` 悬浮层，不占用常驻页面和侧栏入口。 |
| D-04 | “代理”与“聊天”共享会话 UI；聊天模式从能力层面禁用工具、Skill、MCP、工作流及文件写入。 |
| D-05 | 主内容采用固定“聊天”页签加可关闭文件页签；“聊天”页签永远位于首位且不可关闭。 |
| D-06 | 右侧栏和底部面板都可承载文件、终端、内容搜索、日志、会话调试；终端允许多实例，其他面板默认单实例。 |
| D-07 | 所有破坏性动作使用 `AlertDialog`；短反馈用 `Sonner`，持续风险与错误用 `Alert`。 |
| D-08 | 所有管理页共享“标题与说明—统计/状态—筛选工具栏—内容列表—详情层”的骨架。 |
| D-09 | AI 生成的 HTML/CSS/JavaScript 必须经过预览与权限确认，才可加入应用中心或在独立窗口运行。 |
| D-10 | “项目”和“会话”是两个层级：项目决定默认工作目录与上下文，会话记录一次连续交互。 |
| D-11 | `Card` 只用于边界独立、需要整体操作或预览的对象；禁止 Card 套 Card，也禁止把所有区块默认做成卡片。 |
| D-12 | 跨会话、跨模型和跨工具协作统一通过 `docs/协作同步/` 交接进度、任务、决策和风险。 |
| D-13 | 设置中的“连接”是本地 Aestival 与外部消息平台之间的受控桥接，不是 Aestival 登录；默认使用配对/允许列表、群聊提及门控和最小代理权限。 |

## 5. 术语

| 术语 | 定义 |
| --- | --- |
| 代理模式 | 允许模型调用已授权的工具、Skill、MCP、工作流与本地资源。 |
| 聊天模式 | 纯对话模式，禁止任何工具调用和具有副作用的能力。 |
| 项目 | 一组会话共享的工作目录、知识库、权限默认值和上下文。 |
| “任务”项目 | 系统固定、不可删除的默认项目；未选择真实项目时，新会话归入此处。 |
| 会话 | 一次连续对话与代理执行记录，可重命名、归档、Star、分叉或删除。 |
| 工作区面板 | 可放在右侧栏或底部的文件、终端、搜索、日志、会话调试视图。 |
| 临时会话 | 默认不进入历史列表；关闭前可转为普通会话。 |
| 上下文压缩 | 将较早消息压缩为摘要，并保留压缩事件与前后 token 变化。 |

## 6. 资源依赖

方案约定使用以下应用资源：

- 应用图标：`frontend/src/assets/icons/application/logo.svg`
- 状态栏/任务栏模板图标：`frontend/src/assets/icons/application/icon-template.svg`
- 应用内品牌图标：`frontend/src/assets/icons/application/icon.svg`
- 文件和文件夹图标：`frontend/src/assets/icons/material/`
- 文件后缀映射：`docs/文件图标映射.md`

文件图标的来源与命名应跟随 [Material Icon Theme 官方仓库](https://github.com/material-extensions/vscode-material-icon-theme)。其映射支持按文件扩展名、精确文件名、文件夹名和根目录名区分；Aestival 的映射优先级也应遵循“精确文件名 > 复合后缀 > 普通后缀 > 默认文件”的顺序。

当前仓库中上述三个应用图标、Material 图标目录和 `docs/文件图标映射.md` 已出现，但尚未完成品牌视觉、资源来源/许可证、图标名与映射一致性验收。文件存在不等于依赖已经完成；进入 UI 实现前仍须完成对应验收。

## 7. 不在本轮范围内

- 不安装 Tailwind CSS、shadcn/ui、Zustand、Lucide 或 Monaco。
- 不修改 Wails 窗口配置。
- 不实现真实模型、数据库、MCP、Skill、终端、文件系统或定时任务能力。
- 不制作图标、插画、截图或高保真视觉稿。
- 不决定后端协议细节，但文档会标记 UI 需要的数据与状态。

## 8. 设计完成标准

本方案必须满足：

1. 每个功能页面都有入口、主结构、关键操作、空/加载/错误/成功状态。
2. 每项用户给出的能力都能在对应页面或流程中找到承载位置。
3. 全局、项目、会话、消息、输入框、文件与管理页右键菜单均有明确差异。
4. 所有菜单项都有 Lucide 图标；有快捷键的动作在右侧展示快捷键。
5. 所有指定的 shadcn/ui 组件都有合理使用位置或兼容说明。
6. 窄窗口、标准窗口、宽屏，以及 macOS、Windows、Linux 的窗口行为均有定义。
7. 方案可以直接拆成后续 UI 实现任务，不依赖口头补充。
8. 页面不出现卡片嵌套；Card 使用有明确理由，并优先考虑普通分区、列表、表格、Item、Tabs、Accordion 或 Separator。

## 9. 跨会话协作

所有后续 AI 工具和新会话开始工作前，都应先阅读项目根目录 `AGENTS.md` 与 [协作同步说明](../协作同步/README.md)，再根据任务更新当前状态、任务看板、决策记录与变更日志。
