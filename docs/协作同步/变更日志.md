## 2026-07-26 01:05（Asia/Shanghai）— BE-001 第八轮修复：移除隐形标题栏强制拖拽，根治顶部角落缩放抖动（用户已验证）

### 用户反馈与排查

- 第七轮的"缩放期间临时不透明"方案经用户实测无效并已回退。用户提供关键线索：从顶部角落缩到最小尺寸后继续移动鼠标，窗口会往对角"跑位"；抖动表现类似窗口先跑向对角再被拉回。
- 根因确认（Wails v3.0.0-alpha2.117 源码）：全局 `NSEventMaskLeftMouseDown` 监听在每次左键按下时调用 `handleLeftMouseDown:`，只要落点在 `InvisibleTitleBarHeight`（46px）顶部区域内且距左右边缘超过 5px，就立即强制执行 `performWindowDragWithEvent`（移动窗口）。现代 macOS 的角落/边缘缩放手柄大于 5px（Wails 对 issue #4960 的 5px 规避不足），顶部角落按下时 AppKit 同时启动实时缩放：一个模态循环移动窗口、一个缩放窗口，每帧互相拉扯 → 抖动；缩到最小尺寸后缩放钳制但拖拽仍在移动 → 窗口跑位。底部角落不在顶部 46px 区域内，无冲突，因此始终流畅。
- 运行时 JS（`drag.ts`）核实：macOS 上 JS 自定义边缘缩放不启用，缩放为纯原生；CSS `--wails-draggable: drag` 拖拽面经 `wails:drag` → `startDrag()` 独立路径工作，不依赖 InvisibleTitleBarHeight。

### 修改

- `main.go`：移除 `InvisibleTitleBarHeight: 46`，保留 `MacBackdropTranslucent` 与 `MacTitleBarHiddenInsetUnified`（红绿灯位置由后者决定，不受影响）。窗口拖拽改由前端 CSS 拖拽面承担。

### 验证
