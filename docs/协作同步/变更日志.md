# Aestival 协作变更日志

## 2026-07-26 00:11（Asia/Shanghai）— UI-001 第六轮标注修复：侧栏边缘 hover 高亮贯穿标题栏

### 用户反馈与修改

- 用户反馈：鼠标悬停侧栏右缘时，标题栏下方区域出现高亮加粗线，但标题栏那一行没有高亮。
- 原因：`SidebarRail` 以 `-top-[50px]` 上延进入标题栏区域，但它位于内容行的 `z-10` 层叠上下文内，标题栏为 `z-20`；标题栏背景层遮住了 rail 上延段的 hover 高亮线，并拦截了该区域的鼠标事件。
- 修改 `frontend/src/App.tsx`：内容行容器由 `z-10` 调整为 `z-30`。行内容与标题栏垂直方向不重叠，唯一探入标题栏区域的元素是 rail 上延段（已全仓确认），因此仅 rail 上延段的绘制与事件层级移到标题栏之上。
- 效果：hover 高亮线从标题栏连续到底部；标题栏内 16px 侧栏边缘条恢复可 hover、可点击切换侧栏，符合第四轮"可拖拽/hover 边缘从标题栏顶部连续到底部"的意图。

### 验证

- `npm run build`（tsc + Vite production build）通过；仍仅有既知的主 chunk 体积提示。
- 全仓检索确认内容行内无其他负向 top 偏移元素；ContextMenu/DropdownMenu/Tooltip/HoverCard 均为 portaled 浮层，不受行层级调整影响。
- 侧栏收起滑出仍在内容行内进行，与标题栏无垂直重叠，不影响第五轮的同步回缩修复。

## 2026-07-26 00:02（Asia/Shanghai）— UI-001 第五轮标注修复：侧栏与标题栏回缩统一

### 用户反馈与修改

- 用户反馈：侧栏与其上方标题栏区域不是一体，收起侧栏时两者回缩不统一，视觉不一致。
- 原因：标题栏左段按侧栏状态在 `w-[var(--sidebar-width)]` 与 `flex-1` 之间切换并即时增删 `bg-background`/`border-b`，`flex` 与固定宽度之间无法插值，导致侧栏上方区域瞬间跳变，而侧栏与材质层以 200ms 滑出。
- 修改 `frontend/src/components/shell/app-titlebar.tsx`：标题栏改为固定单行布局，72px 安全区、侧栏切换、标题与右侧按钮位置不再随侧栏状态变化（符合设计方案 01 第 7 节）；实体背景与底边抽为独立背景层，其左缘在展开态位于 `var(--sidebar-width)`、收起态位于 0，以 `transition-[left] 200ms ease-linear` 与侧栏容器、全高材质层的滑出完全同步。
- 展开态视觉不变：左 256px 仍透出整列毛玻璃；收起末态不变：标题栏恢复全宽实体底边。

### 验证

- `npm run build`（tsc + Vite production build）通过；仍仅有既知的主 chunk 体积提示。
- 同步核对三处动画参数：侧栏容器 `transition-[left] 200ms ease-linear`、材质层 `transition-transform 200ms ease-linear`、标题栏背景层 `transition-[left] 200ms ease-linear`，整列右缘位置在任意时刻一致。
- 标题栏仍保留 z-20，SidebarRail 上延 50px 的事件层级与内缩 8px 拖拽面行为不变；`prefers-reduced-motion` 下动画照常降级。

## 2026-07-25 23:31（Asia/Shanghai）— UI-001 第四轮标注调整

### 用户反馈与修改

- 整列 Sidebar 材质层由 80% 侧栏色染色调整为 60%，并由固定定位改为应用根容器内的绝对定位；Wails 原生 `MacBackdropTranslucent` 继续负责毛玻璃模糊。
