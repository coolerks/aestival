# Aestival 跨会话协作同步说明

本目录用于不同 AI 模型、不同工具和不同会话之间同步项目进度。它保存的是可继续工作的事实，不替代设计方案、代码或 Git 历史。

## 1. 目录职责

| 文件 | 职责 | 更新时机 |
| --- | --- | --- |
| [当前状态.md](./当前状态.md) | 当前阶段、整体完成度、正在做什么、下一步 | 每次实质工作结束 |
| [任务看板.md](./任务看板.md) | 任务 ID、负责人、状态、依赖、验收 | 开始领取与结束交付 |
| [决策记录.md](./决策记录.md) | 跨模块、会影响后续工作的稳定决策 | 新决策产生或旧决策被替代 |
| [变更日志.md](./变更日志.md) | 每次变更的文件、结果和验证摘要 | 每次实质工作结束 |
| [依赖与风险.md](./依赖与风险.md) | 缺失资源、外部依赖、技术风险和阻塞 | 状态发生变化 |
| [会话交接模板.md](./会话交接模板.md) | 未完成工作或跨工具交接时的标准格式 | 需要详细交接时复制使用 |

## 2. 新会话读取顺序

1. 项目根目录 `AGENTS.md`。
2. 本文件。
3. `当前状态.md`。
4. `任务看板.md`。
5. 与任务相关的设计方案。
6. 相关决策和依赖风险。
7. 目标代码与现有变更。

不要仅依赖聊天历史，因为后续工作可能由其他模型或工具继续。

## 3. 任务状态

只使用以下状态：

| 状态 | 含义 |
| --- | --- |
| 待办 | 已定义但尚未领取 |
| 进行中 | 已有负责人开始处理 |
| 阻塞 | 无法继续，必须写明阻塞条件 |
| 待验收 | 实现完成，等待用户或上游确认 |
| 已完成 | 验收要求已满足，没有剩余必需工作 |
| 已取消 | 明确不再实施，并记录原因 |

“快完成”“差不多”等模糊状态不得写入看板。

## 4. 领取任务

开始前：

1. 在任务看板找到或新增唯一任务 ID。
2. 确认没有其他“进行中”任务修改同一文件或状态域。
3. 将任务状态改为“进行中”。
4. 填写负责人/工具；能获得会话标识时一并记录，不能获得时不要编造。
5. 写明预计修改范围和依赖。

如果目标范围已经有人处理：

- 不覆盖对方任务。
- 优先选择不重叠的子任务。
- 必须重叠时，先由用户或上游协调范围。

## 5. 工作中同步

下列情况应立即更新，而不是等到全部完成：

- 发现设计与实现冲突。
- 新增跨模块决策。
- 发现缺失资源或后端依赖。
- 任务进入阻塞。
- 修改范围明显扩大。
- 验收方式发生变化。

同步文档只写结论、证据和影响，不写隐藏推理。

## 6. 结束工作

按顺序更新：

1. 任务看板：状态、更新时间、验收。
2. 当前状态：整体阶段、完成项、进行中、阻塞、下一步。
3. 变更日志：变更文件、结果、验证。
4. 决策记录：有新决策时追加。
5. 依赖与风险：有变化时更新。

如果任务未完成，保留“进行中”或改为“阻塞”，并使用会话交接模板写清：

- 已完成到哪里。
- 哪些文件已改。
- 哪些验证通过。
- 具体停在什么位置。
- 下一步的第一条可执行动作。

## 7. 状态字段规范

- 日期时间：`YYYY-MM-DD HH:mm`。
- 时区：`Asia/Shanghai`。
- 负责人：模型/工具/人工名称；无信息写“未分配”。
- 文件：使用项目相对路径。
- 任务 ID：
  - `DOC-xxx`：文档与规范。
  - `DES-xxx`：设计评审与设计变更。
  - `DEP-xxx`：依赖与资源。
  - `UI-xxx`：前端 UI。
  - `BE-xxx`：后端/Wails。
  - `QA-xxx`：验证与质量。
- 决策 ID：`DEC-xxx`。
- 风险 ID：`RISK-xxx`。

## 8. 单一事实来源

- 产品与交互细节：`docs/设计方案/`。
- 长期约束：根目录 `AGENTS.md`。
- 当前进度：`当前状态.md`。
- 谁在做什么：`任务看板.md`。
- 为什么这样做：`决策记录.md`。
- 发生过什么：`变更日志.md`。

不要把同一份完整规则复制到多个同步文件。同步文件可以引用设计方案和 AGENTS，但不应另造冲突版本。

## 9. 安全

禁止写入：

- API Key、密码、Token、Cookie、Authorization。
- 未脱敏数据库连接串。
- 用户私密会话正文。
- 系统隐藏推理。
- 可用于恢复敏感数据的完整调试包。

需要记录问题时，只保存脱敏摘要、错误类型和可复现步骤。
