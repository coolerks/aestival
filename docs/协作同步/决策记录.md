## DEC-001：本地优先且无登录

- 决策：不设计登录、注册、云账户或用户 Profile。
- 原因：产品定位是本地桌面 AI Agent 应用。
- 影响：左侧栏底部展示 Aestival 品牌菜单，不展示用户头像和用户名。
- 来源：用户需求、`docs/设计方案/README.md`。

## DEC-002：shadcn/ui 作为强制组件层

- 决策：已有 shadcn/ui 组件不得用手写基础组件替代。
- 原因：保持行为、样式、可访问性和跨工具实现一致。
- 影响：新组件先查本地组件与 registry；业务组件只做组合。
- 来源：用户需求、`AGENTS.md`、组件覆盖矩阵。

## DEC-003：Card 克制且不嵌套

- 决策：允许使用 Card，但它不是默认布局；禁止 Card 套 Card及视觉卡片嵌套。
- 原因：减少层级噪声，避免管理页面退化为卡片墙。
- 影响：优先使用普通分区、Item、Separator、列表、表格、Tabs、Accordion、Collapsible 和 Resizable；指标默认使用指标带。
- 验收：单独执行卡片嵌套与过度卡片化审计。
- 来源：用户补充要求、`docs/设计方案/01-视觉系统与窗口布局.md`。

## DEC-004：窗口与面板布局

- 决策：默认左侧栏 + 主内容；右侧栏按需形成第三列；底部面板是垂直分割。
- 原因：兼顾桌面信息密度与主内容最小宽度。
- 影响：使用 Resizable，并提供收起、恢复和窄窗口降级。

## DEC-005：统一右键系统

- 决策：全局禁用浏览器原生右键，按区域使用 shadcn `ContextMenu`。
- 原因：保证菜单图标、快捷键、分组、多级菜单和桌面体验一致。
- 影响：Monaco、终端和输入框也要提供区域专用菜单。

## DEC-006：跨会话同步

- 决策：所有模型、工具和会话必须通过本目录同步任务、状态、决策、变更和风险。
- 原因：后续功能可能由不同 AI 工具跨会话实现，聊天历史不能作为唯一上下文。
- 影响：任何实质工作结束前都要更新同步文档；任务需要唯一 ID 和负责人。

## DEC-007：中文文档

- 决策：项目约束、设计、进度、决策、风险和交接文档使用中文。
- 原因：降低跨模型理解偏差，符合项目界面语言。
- 影响：标准 API、库名、代码标识符保留英文。

## DEC-008：设计先行

- 决策：当前阶段先完成并评审 UI 设计，不提前实现 UI。
- 原因：用户明确要求先写设计方案。
- 影响：UI-001 及其后任务必须等待用户明确授权。
- 状态：已被 DEC-010 替代。

## DEC-009：外部消息连接安全边界

- 决策：Telegram、飞书、Discord、钉钉、微信和 QQ 作为设置中的外部消息连接，由本地 Aestival/后台服务接收和回复；它们不是 Aestival 账号系统。
- 默认：私聊采用配对，群组关闭；启用群组后使用允许列表并要求提及。访问控制使用平台稳定 ID，会话按平台、连接实例、来源和话题隔离。
- 权限：外部代理请求继续使用现有审批引擎；远程只能在显式启用后由连接所有者批准一次性低/中风险动作，高风险授权和权限扩大只能在桌面端完成。
- 数据：渠道 Secret、扫码会话与原始 Authorization 进入本地安全存储或 Secret 引用，不进入普通 Zustand、未脱敏日志或导出。
- 原因：外部入口扩大攻击面，但用户仍需要从常用消息平台安全地控制和使用 Aestival。
- 来源：用户需求、`docs/设计方案/08-任务与设置.md` §5。

## DEC-010：进入 UI 与桌面窗口外壳实现

- 决策：从 UI-001、BE-001 开始实现前端 UI、Mock 交互和 Wails 桌面窗口外壳。
- 边界：允许编写与 UI 交互、窗口尺寸、标题栏、面板和前端状态有关的代码；模型、工具、知识库、文件、任务调度等业务服务继续暂缓。
- 数据：当前使用明确标记的 Mock 数据与前端状态，不伪造网络、模型、文件写入或计费成功。
- 原因：用户在 2026-07-25 明确授权进入代码实现，并要求后端业务逻辑待后续讨论。
- 来源：用户当前任务。
